# 运行模式归属换型参数

## 新调用关系

主界面模式选择 → `SettingFrm.ChangeParameterMode` → `DynamicParamForm.ModeChange` → 加载当前产品对应的模式参数 → 更新 `DynamicParam.Instance.运行模式` → 通知主界面模式标签及工站配方任务列表。

- `DynamicParamForm` 管理当前模式；`DynamicParam.OnModeSwitchView` 和 `OnModeSwitch` 分别通知显示及工站任务配置。
- `SingleStationConfigControl` 的配方加载、按模式保存任务列表都改读 `DynamicParam.Instance.运行模式`。
- `CommonParamForm` 不再拥有模式事件、模式切换及当前模式查询。全局保存不再传入模式。
- StationCommon、View 项目增加 DynamicParam 项目引用。必须一起重新编译、部署，不要只替换参数模块 DLL。

## 旧配置与保存

启动沿用原行为：实际运行模式初始化为“正常生产”，不从产品文件恢复上次运行状态。切产品保留当前实际模式，不采用目标产品文件里的旧模式值。

旧 `CommonParam.para` 中的“运行模式”在加载时从内存副本移除；产品主参数中缺少该项时，在内存中补齐。加载、切模式、切产品不自动写参数文件。

手动保存全局参数后，旧项才从全局文件移除；手动保存换型参数后，新项写入当前产品主文件（例如 `AudioAirPods.para`）。不批量修改其他产品及 FT050S1/FT050S2 配置包。

该项仍是框架状态：只读、不可删除或转回全局、不能加入 `<产品>_<模式>.para` 覆盖表。编辑器保存会补齐该状态项，不能通过“清空”移除。实际模式切换仍使用主界面的模式切换入口，不能以脚本直接改值代替完整切换流程。

运行模式现在依赖成功加载的当前产品：必须启用 SoftwareConfig 的换型参数功能并配置有效产品。未启用或加载失败时明确报错，不再回退到全局模式。

## 部署前必须调整的设备脚本（本次未修改）

FT050S1 中以下文件仍读取 `CommonParam.Instance.运行模式`，部署前需改为 `DynamicParam.Instance.运行模式` 并重新编译任务：

- `Task/流线测试A/Run.cs`
- `Task/流线测试B/Run.cs`
- `Task/回流线/Run.cs`
- `Task/工位1XYD/Run.cs`
- `Task/工位2XYD/Run.cs`
- `Task/CCD动静态测试/Run.cs`

不提供旧全局调用别名。脚本未改时旧读取会失败，不能直接恢复设备生产。其他设备脚本和已编译的第三方程序集也需要部署前审查；本次清单以 FT050S1 为例，不代表其他设备已验证。

## 验证边界

自动测试使用临时参数文件，覆盖旧全局项过滤、只读产品模式生成、手动保存、模式切换不写盘、切产品保留当前模式、模式覆盖表拒绝及非法配置加载不改变原参数状态。同时回归参数显示名称、双向转移及显式赋值同步。

未执行设备联机、真实任务启停、HIVE/MES 及工站配方现场验证。编译和临时配置测试不代替这些验收。
