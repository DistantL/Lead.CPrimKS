# 全局参数与当前产品换型参数双向转移

## 操作步骤

1. 停止设备运行，以允许编辑参数的高级权限登录。先保存全局、换型参数页已有的修改。
2. 进入“全局参数 → 编辑参数”，选中顶层参数，右键选择“转移变量”。
3. 在“转移为换型参数”弹窗选择当前产品已有分组，或直接输入新分组名。类型、索引名称、显示名称只读；窗体与“修改属性”使用相同控件及灰色风格。
4. 点击“确定”仅暂存，参数从编辑器的全局列表移除；可以继续转移其他参数。
5. 点击参数配置窗口顶部“保存”，统一提交全局文件与当前产品文件。关闭窗口并确认放弃则取消尚未保存的转移。

转移只影响当前产品主文件，例如 AudioAirPods.para；不加入任何产品模式文件、不更新其他产品。
取消转移弹窗不改变编辑内容。当前产品没有分组时也可直接输入。分组名去除首尾空白，不允许全空白；同次编辑中新输入的组可供后续转移选择。顶部保存后，参数的 Category 属性形成新分组，不创建额外分组文件。

## 反向转移：换型参数 → 全局参数

在“换型参数 → 编辑参数”中选中顶层参数，右键“转移变量”，弹窗标题为“转移为全局参数”。
类型、索引名称、显示名称仍只读；分组取全局参数已有分组，也可直接输入新组名。
确定仅暂存，顶部保存才统一提交当前产品文件与全局文件；取消和关闭放弃不写入。
只移除当前产品的定义，其他产品同名定义保持不变；新全局定义会由所有产品共享。

若当前产品任何运行模式文件仍引用该变量，则拒绝转移并提示文件路径。
请先在对应模式中移除该模式参数并保存，再重新打开编辑器执行转移。
本功能不会自动清理或改写模式文件；提交前还会复查所有支持模式文件的快照和变量引用。
反向转移后，需手动把相关 DynamicParam.Instance.变量名 读写改为 CommonParam.Instance.变量名。

## 全局转移到换型时的调用调整

转移不提供兼容转发，也不修改任务脚本。保存后，原来的 CommonParam.Instance.变量名
需要改为 DynamicParam.Instance.变量名，读和写都需要检查。
框架和脚本可能直接依赖某些全局参数；除了被禁止转移的“运行模式”，也不能假定其他变量可无风险转移。
恢复设备运行前，应完成引用检查、调用调整、编译和现场验证。

## 文件保存与恢复

- 使用已加载的全局目录、产品文件和当前模式；不采用尚未重启生效的新路径。
- 目标同索引名称、重复待转移、未保存页面数据、产品或模式变化、权限或运行状态变化、文件外部改动都会阻止提交；反向转移还会检查全部支持模式对变量的引用。
- 提交前验证两份 XML 和当前产品模式兼容性，准备临时文件及备份，然后先替换目标文件，再替换源文件。
- 备份与原文件同目录，名称为“原文件名.transfer-唯一标识.bak”；成功后也保留备份。
- 替换或刷新失败会尝试恢复原文件和界面；错误信息给出备份位置。恢复失败时不要运行设备，先核对并人工恢复。
- 两文件协调保存并非跨文件系统事务：断电或强制结束进程不能保证自动恢复。发生此类中断，应核对两份文件，必要时从同一次操作的备份恢复。
- 保存成功后只刷新两侧内存及界面，不调用会再次写文件的加载流程。模式文件不因转移而创建或改写。
