# 显式赋值同步与手动保存

## 操作规则

- CommonParam.Instance.参数 = 值、DynamicParam.Instance.参数 = 值、SetMember，以及自定义类型子属性赋值，更新运行内存并通知 UI。
- 刷新在 UI 线程执行，密集赋值合并为最新值；暂停启用编辑及保存前同步处理尚未消费的赋值快照。
- 赋值不自动写文件。只有明确保存才将当前 UI 值写入对应参数文件。
- 点位列表原地改坐标或增删元素不会触发 UI 通知。需要同步时重新赋给原参数；通知快照与运行列表相互独立。
- 原地修改不能通过修改另一个参数、刷新点位树或点击保存而被夹带进入 UI/文件。显式重新赋值整个列表才提交列表当前内容。
- 既有公开 Save API 仍是明确的保存请求；本功能没有禁止脚本主动调用保存接口。上述不自动落盘针对普通赋值、加载、模式切换和界面刷新。
- 支持已有普通类型、整组点位及自定义类型；Other 缺少完整类型约定，明确拒绝赋值同步。

## 模式规则

启动/换产品加载主文件并应用当前模式一次。同产品切换模式在当前 UI 缓存上应用目标模式，空模式不恢复覆盖前值；这些操作不写参数文件。
主参数文件缺失时报错，不再静默创建；缺失的模式文件在内存中按空表处理。

脚本修改换型值不反写模式表。普通保存只保存当前换型值；模式文件未被人工修改时不重写。
人工修改、新增模式项后保存，只应用实际改值/新增的项；移除模式项不回退当前换型值。
切换产品或重启不承诺保留尚未保存的修改，部署前请明确保存。

## 一致性保护

运行参数对象和 UI 列表相互独立。赋值锁保护运行属性、XML 快照与版本；通知在锁外发送。
保存期间使用同一赋值锁，不接受并发过期快照；主程序还检查运行/复位状态。
旧版本编辑器或转移会话拒绝保存；重新加载会清空旧通知，旧产品通知不会覆盖新上下文。
编辑器从当前 UI 快照开始，而非从磁盘旧值开始。取消窗口不执行磁盘重载。
双向转移使用两侧 UI 快照，保留已应用但未落盘的模式值，失败时分别恢复原文件与原界面快照。

显式保存会生成同目录 .save-唯一标识.bak 备份，失败尝试回滚；模式文件需写入时与产品文件协调提交。
两文件保存不是断电事务。断电或强杀后需核对配置，必要时使用同一次操作的备份恢复。
